## 🏗️ v2.0.0 Architecture Changes

**PRIORITY ORDER:** Streaming → Core Infrastructure → Discovery → Social → Polish

### Phase 1: Bulletproof Streaming (Week 1-2)
**Goal:** ZERO playback failures - Multi-source fallback + stream health

**Tasks:**
1. **Integrate MultiSourceResolver** (USE experimental file)
   - Wire `multi_source_resolver.dart` into existing player screens
   - Automatic fallback: VidSrc → Videasy → Amri (3 sources)
   - Show "Source: VidSrc" indicator in player UI
   - Add manual "Switch Source" button for user override

2. **Integrate NetworkClient** (USE experimental file)
   - Replace all `http` calls with `NetworkClient().get()`
   - Enable DoH by default (Cloudflare + Google DNS)
   - ISP-blocking bypass automatic
   - Add "Network: Standard / DoH" toggle in Settings

3. **Stream Health Monitoring**
   - Track success/failure rate per source
   - Cache successful source per title (1-hour TTL)
   - Auto-prioritize fastest/most reliable source
   - Show source stats in debug mode

4. **Error Recovery UI**
   - "Playback failed, trying next source..." loading state
   - Retry button with manual source selection
   - Fallback to lower quality if all HD sources fail

**Deliverables:**
- **95%+ playback success rate** (vs 70% currently)
- ISP-proof streaming (DoH bypass)
- User confidence (always finds working stream)
- Source reliability data for optimization

---

### Phase 2: Core Infrastructure (Week 3)
**Goal:** Lightning-fast UX with cache-first architecture

**Tasks:**
1. **Deploy CacheEngine** (USE experimental file)
   - Wrap all API calls (TMDB/AniList/Manga/Music/Books) with cache layer
   - Stale-while-revalidate: show cached instantly, refresh in background
   - Persistent cache across app restarts
   - Add cache stats in Settings (size, hit rate, clear button)

2. **Performance Optimization**
   - App cold start < 2s (warm < 0.5s)
   - Home screen instant load (cached catalog)
   - Measure metrics: load time, cache hit rate

3. **Testing**
   - Verify ISP-blocked domains work via DoH
   - Cache corruption recovery
   - Offline behavior (show cached content)

**Deliverables:**
- **3x faster app startup**
- Offline-first feel (cached data)
- Reduced API costs (fewer requests)

**Deliverables:**

### Phase 4: Offline Downloads (Week 5)
**Goal:** Watch/listen without internet

**Tasks:**

2. **Storage Management**
   - Download location: internal storage (default) or SD card
   - Storage limit setting (1GB/5GB/10GB/Unlimited)
   - Auto-delete watched content (optional)
   - Show storage usage stats

3. **Offline Playback**
   - Downloaded content plays without internet

   - Music download with album art + metadata
   - Manga chapter batch download (entire arc/volume)

4. **Implementation**
   - Use `flutter_downloader` package
   - Encrypt downloaded files (DRM-lite, prevent sharing)
   - Background downloads (WorkManager Android, BackgroundTasks iOS)

**Deliverables:**
- Full offline mode (watch/listen anywhere)
- Smart storage management
- Reliable download system

### Phase 7: AI Recommendations (Week 9)
**Goal:** Personalized discovery with GPT-4

**Tasks:**
1. **Taste Profile Engine**
   - Track user behavior: watch history, ratings, search queries
   - Build preference vector: genres, actors, directors, eras
   - Store locally (privacy-first)

2. **GPT-4 Recommendation API**
   - Send anonymized taste profile to GPT-4
   - Prompt: "User loves sci-fi thrillers like Inception, watched 20 anime last month, rated 5★ to Dark. Recommend 10 movies/shows with reasons."
   - Parse GPT response → title suggestions + reasoning
   - Cache recommendations (refresh weekly)

3. **Recommendation UI**
   - "For You" tab (AI-curated homepage)
   - "Because you watched X" cards with reasoning
   - Surprise me! (random high-match suggestion)
   - Feedback buttons (👍 good rec / 👎 not interested)

4. **Privacy & Cost**
   - User opt-in required (settings toggle)
   - Anonymous profiles (no PII sent to OpenAI)
   - Rate limit: 10 GPT calls/day per user
   - Fallback: rule-based recs if GPT fails

**Deliverables:**
- Personalized AI recommendations
- "Because you watched..." with reasoning
- Privacy-respecting implementation

## 🛡️ Risk Mitigation

| Risk | Mitigation |
|------|------------|
| DoH breaks in some regions | Fallback to standard DNS, user toggle |
| Cache corruption | Version cache files, auto-rebuild on error |
| Multi-source all fail | Show helpful error, link to issue tracker |
| YouTube extractor rate limit | Exponential backoff, cache successful extractions |
| Increased complexity | Feature flags, gradual rollout, revert plan |
